# WEEK03~15 개념-코드-CVE 학습 설계 v4

## 이 개편에서 해결할 문제

기존 과정은 안전 범위와 공식 출처를 잘 지키지만, WEEK06 이후의 많은 모듈이 `질문 → 두 문단 → 짧은 그림 → 오해 → 확인 문제`로 반복된다. 학생은 용어를 고를 수 있어도 값이 어느 형태로 이동하고, 어떤 조건문 또는 API 호출에서 신뢰 경계가 무너졌는지 설명하기 어렵다. CVE 카드도 공식 기록을 과장하지 않는 대신 제품의 역할, 실제 수정 줄, 회귀 시험까지 내려가지 못했다.

이번 개편의 기준은 CVE 개수가 아니다. 한 학습 흐름 안에서 다음 질문에 차례로 답할 수 있어야 한다.

1. 이 기능이 없으면 어떤 개발·운영 문제가 생기는가?
2. 정상 입력은 누가 만들고, 어떤 표현으로 바뀌며, 어디까지 이동하는가?
3. 어느 구성요소가 외부 값을 데이터로 다룰 책임을 갖는가?
4. 취약한 구현은 정상 경로와 어느 줄에서 갈라지는가?
5. 그 줄 뒤에서 값·메모리·권한·프로토콜 상태가 어떻게 달라지는가?
6. 실제 제품의 CVE도 같은 경계에서 실패했는가?
7. 확인 가능한 공식 패치는 정확히 무엇을 바꿨는가?
8. 실제 공격을 재현하지 않고도 어떤 상태 차이를 관찰할 수 있는가?
9. 코드 수정 뒤 설정·권한·로그·회귀 시험은 각각 무엇을 확인하는가?

## 플랫폼 데이터 계약

### `mechanism`

정의 표가 아니라 필요한 상황에서 정상 동작까지 이어지는 블록이다. 처음 등장하는 용어에는 `무엇인지`, `왜 필요한지`, `비슷한 말과의 차이`를 함께 적는다. 각 단계는 행위자, 들어오는 데이터의 형태, 수행하는 동작, 다음 단계에 넘기는 형태를 가진다. `trustBoundary`는 경계 앞의 값, 판단 책임, 통과 뒤 허용되는 동작, 실패했을 때의 결과를 명시한다.

### `code-trace`

코드를 보여 주는 이유와 출처 수준을 화면 상단에 고정한다.

- `official-source`: 공식 저장소의 실제 소스 일부
- `official-patch`: 공식 수정 commit 또는 PR의 실제 diff 일부
- `educational-model`: 정상 구조나 취약 구조를 단순화한 교육용 코드

교육용 모델은 다음 고지를 숨길 수 없다.

> 아래 코드는 실제 프로젝트 소스 코드가 아니라, 공식 취약점 설명과 패치 구조를 단순화한 재현용 예제이다.

각 주석은 코드 줄, 그 줄 직전 상태, 실행 동작, 실행 뒤 상태를 연결한다. 실제 소스에는 공식 URL과 파일·함수 위치를 붙인다.

### `patch-analysis`

수정 전·후 코드를 나란히 보여 주되, 확인되지 않은 코드를 만들지 않는다. 공개 소스가 없으면 `educational-model`로 표시하고 벤더가 공개한 사실과 교육용 수정 원리를 분리한다. 삭제·추가·처리 순서 변화, 공격 또는 오류 경로가 끊기는 위치, 호환성 한계, 공식 회귀 테스트 유무와 제품 차원의 회귀 항목을 기록한다.

### `impact-map`

기밀성·무결성·가용성을 각각 조건과 함께 쓴다. 인증 필요 여부, 사용자 상호작용, 네트워크 도달성, 기본 설정 노출, 보호 장치가 있을 때 달라지는 결과를 CVSS 약어 대신 문장으로 설명한다. 공격자가 제어하는 값과 직접 제어하지 못하는 서버 상태도 분리한다.

### 확장된 `cve-case`

모든 사례에 제품 역할, 취약점 유형, 영향/수정 버전, 공격 전제, 공격자 제어 값, 제어할 수 없는 값, 실제 운영 영향을 추가한다. CVE 카드는 배경을 대신하지 않으며, 앞선 정상 동작과 실패 코드가 준비된 뒤에만 읽도록 배치한다.

## 공식 근거와 교육용 모델의 판정 규칙

1. 공식 저장소 commit·PR의 파일과 줄을 확인한 경우에만 실제 패치 코드라고 쓴다.
2. 벤더 권고에 버전과 원인만 있고 제품 소스가 공개되지 않았다면 실제 코드처럼 재구성하지 않는다.
3. 표준 문서에서 도출한 프로토콜 상태 예시는 `표준 기반 교육용 모델`이며 특정 제품 구현이라고 부르지 않는다.
4. 공식 diff에 회귀 테스트가 없으면 “공식 diff에서 전용 회귀 테스트를 확인하지 못함”이라고 적고, 별도로 제품 차원의 필요한 시험을 제시한다.
5. CVE와 주차 개념 사이에 직접 인과가 없으면 사례를 억지로 붙이지 않는다. 같은 CVE를 다른 렌즈로 다시 쓸 때는 무엇이 공식 원인이고 무엇이 학습용 관찰 관점인지 매번 구분한다.

## WEEK03 공식 패치 기준선

### RESTEasy · CVE-2020-10688

Red Hat 추적 항목은 영향 범위를 `3.11.1.Final 이전`과 `4.5.3.Final 이전`으로 설명하고 upstream PR #2320을 연결한다. PR의 실제 변경은 `StringParameterInjector`의 여러 예외 경로에서 원래 `strVal`을 메시지 생성기로 전달하던 코드를 `_encode(strVal)`로 바꾸고, `URLEncoder.encode(..., UTF-8)` 보조 함수를 추가한 것이다. 공개 PR의 변경 파일 목록에는 전용 회귀 테스트가 보이지 않는다. 따라서 수업은 “중복 디코딩” 같은 별도 예제를 이 CVE의 실제 원인 코드로 쓰지 않는다.

### GitLab · CVE-2022-1948

공식 commit `e61e9b94`는 quick action contact 자동완성 템플릿에서 이미 escape하던 `email`뿐 아니라 `firstName`과 `lastName`에도 `escape()`를 적용했다. 같은 commit은 세 필드 모두를 확인하는 frontend 회귀 테스트를 추가했다. 저장된 이름이 자동완성 HTML 문자열로 들어가는 실제 경계를 그대로 설명할 수 있다.

### jQuery · CVE-2020-11022

공식 commit `1d61fd94`는 `htmlPrefilter`가 자기 닫힘 태그 형태를 정규식으로 바꾸던 처리를 제거하고 입력 HTML을 그대로 반환하도록 했다. 공식 3.5.0 릴리스는 이 동작 변화가 호환성에 영향을 줄 수 있음을 함께 설명한다. 수업은 위험 문자열을 재현하지 않고, “정화된 문자열 → prefilter 변환 → 브라우저 파서”의 상태 경계와 정상 마크업 회귀만 다룬다.

## 순차 구현·검수 게이트

각 주차는 다음 주차로 넘어가기 전에 아래를 코드와 렌더링 결과에서 확인한다.

- 수정된 목표가 기능 이름 암기가 아니라 흐름 설명·코드 추적·패치 판독 능력을 말한다.
- 주요 개념마다 필요한 상황, 처음 쓰는 용어, 정상 흐름, 경계, 최소 코드가 있다.
- 취약 코드 또는 오류 모델에서 실패 줄과 전후 상태가 보인다.
- 실제 CVE의 제품 역할, 버전, 전제, 제어 값, 영향 조건이 있다.
- 실제 패치와 교육용 코드를 시각적으로 오인할 수 없다.
- 정상·경계·거절·인접 경로 회귀 시험이 있다.
- 실습은 고정 합성 자료, 로컬 sandbox 또는 공식 허가 Lab만 사용한다.
- 출처 링크가 실제 주장과 직접 연결되고, NVD 하나로 패치 설명을 대신하지 않는다.
- 모바일 360px에서 코드·diff·상태표가 가로 화면을 넘기지 않는다.
- 단위 검사, lint, build, 주요 Playwright 경로를 통과한다.
