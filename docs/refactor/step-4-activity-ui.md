# STEP 4 활동 유형별 UI

## 화면과 완료 조건

| 유형 | 화면 구성 | 완료 조건 |
|---|---|---|
| `exploration` | 직무 지도, 검색, 보기 전환, 관심, 메모 | 관심 직무·탐색 노드·메모. 힌트·증거·자동 판정 없음 |
| `practice` | 문제, 입력·선택, 결과 확인, 오답 설명, 재시도, 단계형 힌트 | 결과 확인과 필수 실습 기록 |
| `investigation` | 관찰 대상, 가설, 절차, 관찰, 결론, 가설과 결과 차이 | 관찰 확인과 필수 조사 기록 |
| `simulation` | 상태 변경, 변화 관찰, 예상·실제 비교, 초기화 | 변화 관찰, 기록, 초기화 확인 |
| `external` | 제공기관·공식 링크, 범위 확인, 자기 확인, 수행 기록 | 범위·마스킹·플랫폼 체크와 실습 기록. 사이트는 외부 결과를 판정하지 않음 |
| `assessment` | 진단 또는 이해 확인 | 문항 기준 충족. 일반 실습 기록과 힌트 없음 |
| `report` | Finding 편집기, 품질 점검, 마스킹, 미리보기, 내보내기, 재시험 | 지원 프로필의 품질·마스킹 기준 충족 |

## 일반 실습 기록

기존 `evidence[labId]`는 삭제하지 않는다. 새 입력은 `activityRecords[labId]`에 저장하며, 이전 값이 있으면 화면을 처음 열 때 수행 순서·관찰·설명·마스킹 상태를 읽어 표시한다.

- practice: 수행 순서, 관찰 결과, 원리, 막힌 지점, 힌트 뒤 판단, 재시도 항목
- investigation: 가설, 절차, 관찰, 결론, 가설 차이, 막힌 지점, 재시험 항목
- simulation: 예상, 바꾼 상태, 실제 변화, 비교, 다음 실험, 초기화 확인
- external: 목표, 도구, 원리, 막힌 지점, 결과, 범위·마스킹 확인

힌트를 열면 `labs[labId].hintLevel`과 `hintUsage[labId]`에 각각 UI 상태와 사용 이력을 남긴다. 완료·숙련도에는 직접 영향을 주지 않는다.

## 브라우저 확인

- exploration: 단계별 힌트 0, 실습 증거 0, 자동 검증 문구 0
- practice: 단계별 힌트와 결과 확인, 유형별 실습 기록 존재
- investigation: 가설·관찰·결론·차이 필드 존재, 새로고침 보존
- simulation: 예상·실제·초기화 필드 존재, 힌트 없음
- external: 힌트 없음, 학습자 자기 확인, 자동 검증 문구 0
- assessment: 힌트와 일반 실습 기록 없음
