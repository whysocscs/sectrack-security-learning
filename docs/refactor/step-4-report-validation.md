# STEP 4 보고서 검사

## 공통 검사

1. 제목에 위치·유형·영향이 드러나는가
2. 자산·대상·입력이 있는가
3. 재현 단계가 번호 순서로 3단계 이상인가
4. 관찰과 기대 결과를 구분했는가
5. 기술·비즈니스 영향을 구분했는가
6. 근본 원인과 빠진 통제를 설명했는가
7. 근본 수정과 구체적 변경이 있는가
8. 요청·응답·코드 또는 분석 자료가 있는가
9. 자격 증명과 비밀정보를 마스킹했는가
10. 같은 조건의 재시험 절차가 있는가
11. 가능성·영향 근거가 있는가
12. CWE와 테스트 표준 매핑이 있는가
13. 입력한 CVSS Vector·Score 형식이 유효한가

공통 제목 검사는 `XSS` 문자열을 요구하지 않는다.

## XSS 검사

- Source·Transform·Sink·Context
- 마커 반사와 실행 확인의 구분
- 출력 컨텍스트에 맞는 근본 방어
- CSP·Cookie 보조 통제와 위험 Sink 제거의 구분

## CVSS

- 3.1은 8개 기본 metric, 4.0은 11개 기본 metric의 존재와 허용 값을 검사한다.
- 점수를 자체 계산하거나 추천하지 않는다.
- Score를 입력하면 0~10 범위만 검사한다.

## 마스킹

Cookie, Set-Cookie, Authorization, API Key, JWT, PEM 개인키 패턴을 찾는다. UI의 마스킹 버튼과 Markdown 내보내기는 요청·응답만이 아니라 Finding 객체의 모든 문자열과 중첩 필드에 적용된다.

Node 테스트에서 공통·XSS 검사 분리, 비 XSS 제목 허용, CVSS 3.1·4.0, 미구현 프로필 상태, 샘플 답안 비우기, 전체 필드 마스킹을 확인했다.
